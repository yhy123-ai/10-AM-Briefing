# 十点晨报 · 10 AM Briefing

围绕时政、金融与 AI 科技的信息阅读产品，将分散的新闻整理为按日期归档、带来源链接、可回溯检索的晨报。

**[在线体验](https://ten-am-briefing.nimble-ibex-6140.chatgpt.site)** · **[另一个作品：钢铁荒原](https://github.com/yhy123-ai/Wasteland-Tanks)**

## 项目出发点

日常信息阅读常遇到三个问题：同一事件重复出现、摘要缺少原始出处、读过的信息难以找回。十点晨报围绕“浏览精选 → 阅读详情 → 核查来源 → 历史检索”组织页面，并通过稿件校验、版本记录与发布流程支持持续内容维护。

本项目展示产品流程设计、前后端实现，以及内容整理与发布工具之间的衔接。

## 已实现的功能

| 模块 | 内容 |
| --- | --- |
| 晨报首页 | 按日期浏览时政、金融、AI 科技栏目 |
| 新闻详情 | 摘要、正文、背景、时间线、术语解释与来源链接 |
| 历史检索 | 关键词、栏目和日期区间组合查询，以及分页 |
| 稿件校验 | 日期、截稿时间、来源白名单、事件去重与栏目条数校验 |
| 内容维护 | 草稿入库、发布、补录替换与修订记录 |
| 邮件工具 | 邮件预览、发布后投递、重复发送保护和失败状态记录 |

## 阅读与发布流程

读者侧：打开首页选择晨报 → 进入新闻详情 → 查看原始来源 → 通过历史页找回内容。

维护侧：整理并核查稿件 → 校验结构和来源 → 保存草稿 → 发布指定日期的晨报 → 按需生成或投递邮件。

内容采集、事实核查和定时触发需要配套工作流程。仓库中的网站与工具不会仅因部署完成就自动获得新闻采集或每日调度能力。

## 技术实现

- **界面**：React、TypeScript、Tailwind CSS、组件库。
- **应用框架**：Vinext，采用 App Router 风格的页面与 API 路由。
- **运行与数据**：Cloudflare Workers、D1、Drizzle ORM。
- **辅助流程**：Python 稿件与邮件工具，Windows 本机凭据加密。
- **托管**：Sites，保留原项目的托管清单。

核心数据按“晨报期次 / 新闻条目 / 修订记录”组织。内部写入接口通过运行环境中的 `INGEST_SECRET` 校验访问；公开阅读接口与内容维护接口分开。

## 本地运行

需要 Node.js 22.13 或以上版本。Python 工具需要 Python 3。

```sh
npm ci
npm run dev
```

该项目沿用 Sites 的 Cloudflare / D1 集成。完整阅读与写入流程需要对应的数据库结构和数据，不能仅启动一个静态页面。数据库迁移位于 `drizzle/`；`scripts/local-seed.py` 仅面向已生成的本地 D1 模拟数据库，不会迁移云端数据库。

```sh
npm run build
```

部署前需配置 Cloudflare / Sites 运行环境、D1 绑定和内部写入凭据。原 Sites 项目 ID 保留用于追溯，复制项目部署时应使用自己的项目配置。

## 校验

```sh
node --experimental-strip-types --test tests/domain.test.ts tests/reselection.test.ts
python tests/mail_test.py
```

测试覆盖截稿时间、来源域名、重复事件、搜索参数、补录规则、邮件内容转义、去重与重试。邮件测试使用模拟 SMTP，不发送真实邮件。

公开源码不包含 SMTP 授权码、内部写入密钥、本机加密凭据和个人运行记录。邮件工具中的个人地址已替换为 `your-mailbox@qq.com`，实际使用前需自行配置。运行测试的结果以当前环境执行输出为准。

## 当前边界与后续方向

当前版本保留既有的新闻数据与编辑流程；在线内容更新状态应以站内日期为准。可继续完善内容新鲜度提示、采集任务可观测性和编辑后台，并增加浏览器端的检索与阅读流程测试。
